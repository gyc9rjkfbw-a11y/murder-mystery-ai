# 迷案 · AI 剧本杀

一个可单人试玩、也可 4-6 人真联机的 AI 剧本杀 Web 游戏。

## 功能亮点

- **单人 / 联机**：本地 AI 玩家补位，或通过 5 位房号和朋友开房。
- **服务端权威**：阶段、轮次、线索、投票和胜负由房间服务器统一推进。
- **严格信息隔离**：服务器按座位裁剪剧本、真相、任务和私有线索。
- **实时沟通**：WebRTC 语音与公屏文字，不方便开麦也能完成整局。
- **推理工作台**：时间线标记、嫌疑人评估、线索关联和结案摘要均在本地保存。
- **分幕阅读**：长剧本拆成入戏、暗潮、案发、人心与守则，支持阅读进度和时间线跳转。
- **自定义剧本**：导入或粘贴完整 JSON 剧本，本地保存后可直接开单人局或联机房。
- **剧本防重复**：记录最近 30 场案件指纹，AI 生成重复时自动要求重写，仍重复则拒绝开局。
- **PWA / 桌面 App**：支持安装到桌面、离线外壳和独立窗口运行。

> 依据《一、核心系统架构设计（软件的大脑与骨架）》与《指令.docx（剧本杀 AI 游戏引擎系统指令）》实现的 MVP。
> 技术栈：**Vue 3 + Vite + TypeScript + Pinia + Vue Router**（移动端优先 H5）+
> **Node + ws 房间服务器**（真联机：房号加入、服务端按座位下发、轮次与投票全同步）。
> 想直接和朋友开局：跳到「[一之二、联机](#一之二联机和朋友一起玩真后端)」。

## 一、快速开始

```bash
# 安装依赖（本机已装好，可直接跳到下一步）
pnpm install

# 开发模式（默认 http://127.0.0.1:5273）
pnpm dev

# 类型检查 + 生产构建
pnpm build

# 预览构建产物
pnpm preview

# 只想双击就玩：打成桌面 App（→ 桌面\迷案，自带 Node，关窗即退）
pnpm app
```

> 打好的 App 就在 `桌面\迷案`：双击「迷案.vbs」或桌面上的「迷案」图标即可。
> 详见「一之六、打包成桌面 App」。

> 若 `pnpm install` 提示 `Ignored build scripts: esbuild`，说明包管理器拦截了安装脚本。
> 本项目已通过 `pnpm-workspace.yaml` 的 `onlyBuiltDependencies` 放行；若仍被拦截，可执行
> `pnpm approve-builds` 并勾选 `esbuild`、`vue-demi`。

浏览器打开后建议用手机的调试视图（Chrome DevTools → 设备工具栏）查看，界面按 390×844 设计。

### 快速体验任意阶段（演示深链）

地址栏 hash 带上 `?demo=1` 就会**用离线引擎自动开一局、并沿真实状态机推进到该阶段**
（不消耗任何 API 额度）：

```
http://127.0.0.1:5273/#/statement?demo=1
http://127.0.0.1:5273/#/poll?demo=1&count=4
http://127.0.0.1:5273/#/reveal?demo=1&count=6&theme=现代·雪山山庄暴风雪山庄
```

可用的阶段：`reading` / `statement` / `search` / `poll` / `organize` / `voting` / `reveal`。
参数：`count`（4-6）、`theme`（任意题材）。`search` 只有 6 人局有，深链会自动补齐人数。

深链是**上帝视角**入口（要能切换角色看剧本、方便截图与排查），所以会自动打开上帝视角，
并在界面上打上「上帝视角」标记；从首页正常开的房间不会打开它。

实现见 `src/services/demoBootstrap.ts`：它由**路由守卫** await（`router/index.ts`），
必须在放行 `/reading` 这类需要剧本的路由之前就把剧本准备好，否则深链会先被弹回 `/room`。
生产环境不需要时，删掉守卫里那一行 `resolveDemoRedirect` 调用即可。

## 一之一、自定义剧本

首页「自定义剧本工坊」的主流程是：**玩家写主题 → AI 生成完整剧本 → 房主确认 → 创建房间分发给玩家**。

1. 在主面板填写题材、氛围、人物关系或特殊要求，并选择 4/5/6 人。
2. 点击「让 AI 生成完整剧本」，使用设置页当前配置的真实大模型或离线引擎。
3. 生成完成后先展示剧本草稿、角色名单与公共线索预览。
4. 点「创建联机房间并分发剧本」，服务器重新校验后保存整局，并按座位裁剪给每位玩家。
5. 也可以直接单人带 AI 试玩。

高级入口继续支持：

1. **下载模板**：导出当前 5 人局的完整 `ScriptPackage` JSON，按同一结构修改。
2. **导入 JSON**：选择本机 `.json` 文件。
3. **粘贴内容**：直接粘贴 JSON，也兼容带 Markdown 代码围栏的模型输出。

导入时会执行完整校验：角色数、凶手唯一性、凶手特权、时间线、线索、字数与 6 人局支线任务。校验通过后剧本保存在当前设备，可覆盖同题材同人数的旧版本。

- **单人带 AI 开局**：跳过 AI 生成，直接按剧本角色数建立本地房间。
- **创建联机房间**：房主把剧本随建房指令发给服务器；服务器重新校验后使用，仍按座位裁剪后才下发给每位玩家。
- 自定义剧本属于用户内容，不写入项目仓库；清除浏览器站点数据会同时删除本地剧本库。

## 一之二、联机：和朋友一起玩（真后端）

单机版只能在本地模拟其他玩家；**联机版**多了一个本地房间服务器，用真实 WebSocket 把
多台设备（手机 / 电脑）接到同一局里。

### 怎么开

```bash
pnpm server:build     # 打包房间服务器（esbuild → server/dist/server.mjs）
pnpm server           # 启动：监听 0.0.0.0:5274，同一个端口既出网页也出 WebSocket
```

启动后终端会直接打印手机能打开的地址：

```
手机同 Wi-Fi 打开：http://192.168.1.100:5274/   ← 用这个联机
🎙️ 现在是 http：手机无法开麦，只能打字；要开麦请配证书或走隧道（见 README）
```

（把 `192.168.1.100` 换成你自己电脑的局域网 IP；`pnpm dev` 的 5273 只用于开发调试。）

**想开麦对质**（浏览器只在 https 下给麦克风）—— 两条路，都实测过：

```bash
pnpm tunnel           # A. 有外网：起隧道，把打印出来的 https 地址发给大家（手机零配置）
pnpm cert             # B. 没外网：生成自签证书，再 pnpm server:tls 用 https 起服务
pnpm server:tls       #    （每台手机装一次证书，步骤见 .tools/lan-cert/README.txt）
```

细节、实测数据与排错都在下面「一之三、沟通：开麦通话 + 公屏打字」。

### 怎么玩

1. 房主在首页填昵称 → 点 **「创建联机房间」** → 等待厅里出现 **5 位房号**；
2. 其他人连同一个 Wi-Fi，用上面那个地址打开网页 → **「我有房间号」** → 输入房号 → 加入；
3. 大家点「准备好了」→ 房主点「开始游戏」；
4. **人不满时空位由 AI 玩家补位**（4 人局差 2 人就补 2 个 AI），所以 2 个人也能开局；
5. 之后所有人被服务器带着走：阅读 → 陈述（轮流发言）→（6 人局搜证）→ 摸底 → 整理 → 投票 → 复盘。

### 谁看得到什么（信息隔离）

这是联机版最要紧的一件事：**服务器只为每个座位生成一份视图**，唯一入口是
`server/src/censor.ts` 的 `censorSeat(room, seatId)`（源码里写明：任何下发都必须过它，
禁止 `JSON.stringify(room)`）。

| 内容 | 对局中：自己 | 对局中：其他人 | 复盘后 |
| --- | --- | --- | --- |
| 自己的完整剧本 | ✅ | — | ✅ |
| 别人的剧本 / 任务 / 时间线 | ❌ 不下发（字段为空） | ❌ | ✅ |
| 谁是凶手（`is_murderer`） | 只有自己是凶手才为 `true` | 恒 `false` | ✅ 真实值 |
| 全局真相（真凶 / 死因 / 时间线） | ❌ 空壳 | ❌ 空壳 | ✅ |
| 凶手特权（直觉提示） | 凶手本人第 2 轮起可见 | ❌ | ✅ 公开 |
| 搜到但未公开的线索 | 自己搜到的那条 ✅ | ❌ | ✅ |
| 座位与角色的对应关系 | 只有自己 | ❌ | ✅ |

联机对局里**上帝视角被强制关闭**（本地演示深链仍然可用）。

### 服务端权威 + 按座位投影

- 阶段、轮次、线索发放、搜证抽取、票型统计、胜负判定全部在服务器算，客户端只发意图；
- 服务器每次变化就给**每个座位单独生成一帧** `view` 推过去，前端把它投影回既有的
  `GameState`（`src/stores/game.ts` 的 `applyServerView`），所以 11 个页面几乎不用改动；
- 阶段变化后前端自动跟着跳页（`src/App.vue` 的 watch → `PHASE_ROUTE`）；
- 断线可重连：座位保留，用 `token` 回到原座位并补发当前视图。

### 快捷自检

```bash
pnpm server:test      # 房间服务器（逐帧隔离审计、完整流程、搜证、提前结算、重连、公屏、语音信令）
node .verify/online.mjs      # 前端联机 E2E：4 人（2 真人+2 AI）、4 真人、6 真人（含搜证）
node .verify/prod-smoke.mjs  # 生产包冒烟：只用真实点击，跑的就是手机要用的那个地址
```

## 一之三、沟通：开麦通话 + 公屏打字

对局里顶栏有一个沟通入口（🎙/💬），点开是底部面板，两个 tab：

| tab | 用途 |
| --- | --- |
| **语音通话**（默认） | 开麦后就一直开着，像打电话一样随时插话对质。说话的人头像会亮金圈，别人不用按键就能听到。 |
| **公屏打字** | 不方便开麦时的备选：文字消息实时同步给全桌，带未读红点、历史补发、快捷短语。 |

设计取向很明确：**语音是主路，打字是兜底**。陈述阶段轮到你时，页面同时给「说完了 · 记录发言」
（打字）和「🎙 开麦说」两个入口；不是你的轮次也能开麦插话或在公屏打字 —— 开不了麦的人
全程只用打字也能把一局玩完。

### 语音是怎么实现的

- **端到端 P2P（WebRTC 全网状）**：一桌最多 6 人 = 最多 15 条连接，手机上完全撑得住。
  音频点对点直连，同一 Wi-Fi 下走局域网，不绕服务器。
- **房间服务器只转发信令**（`voice-join` / `voice-leave` / `voice-mute` / `voice-signal`）。
  它不碰音频、不做混音（没有 SFU/MCU）、**不录音、不落盘**，日志里也不打印 SDP。
  信令只发给指定座位，第三个人收不到（自检脚本里有这条断言）。
- **谁发 offer 是确定性的**：座位号小的一方发，两边算出来一致，不会同时发 offer 打架。
- 静音、是否在麦上由服务器广播（别人能看到 🔇）；说话高亮是本地音量分析（RMS 阈值 +
  8 帧/秒 的去抖），不占带宽。

**跨网络怎么玩（不同 Wi-Fi / 用流量）**：默认**不配 STUN**，因为同 Wi-Fi 下靠 host 候选直连最快，
配一个连不上的 STUN 反而拖慢建连。要跨网络，给两端都设一个 STUN：

```js
localStorage.dsh_voice_stun = 'stun:stun.l.google.com:19302'   // 或在构建时设 VITE_STUN
```

对称 NAT 场景还需要 TURN（本项目没带服务器，需要自己搭 coturn）。
另外两个已知的「连不上」原因：**路由器开了 AP 隔离/客户端隔离**（同 Wi-Fi 也互相不可见）、
大家不在同一网段 —— 这两种情况界面上会显示「连不上」，并把原因写在面板里，此时改用公屏打字即可。

### ⚠️ 开麦需要 https（最重要的一条）

浏览器的安全策略规定：**只有安全上下文（https 或 localhost）才允许网页调麦克风**。
所以手机用 `http://192.168.1.100:5274` 打开时，`navigator.mediaDevices` 根本不存在 ——
不是手机的问题，也不是代码的问题，换 https 立刻就好。面板会把这个原因写在界面上，
并给一个「去打字 →」的按钮。

两条拿到 https 的路（**两条都实测过**，见下面的数据）：

**A. 隧道（推荐，手机零配置）** —— 有外网时最省事，域名自带可信证书。
本机已经下好了 `cloudflared`，直接用：

```powershell
& .\.tools\cloudflared.exe tunnel --url http://127.0.0.1:5274 --no-autoupdate
# 打印一行：https://<随机词>.trycloudflare.com
```

把这个 https 地址发给朋友（**不在同一 Wi-Fi 也能玩**）。实测数据：

| 检查项 | 隧道 | 自签证书 | 现在的 http 地址 |
| --- | --- | --- | --- |
| 页面能打开 | ✅ | ✅ | ✅ |
| `isSecureContext` | ✅ `true` | ✅ `true` | ❌ `false` |
| `navigator.mediaDevices` | ✅ `object` | ✅ `object` | ❌ `undefined` |
| 真调 `getUserMedia` | ✅ `GRANTED` | ✅ `GRANTED` | 连函数都没有 |
| `wss` 握手并收到 `welcome` | ✅ | ✅ | ✅ |

- 前端不用改：https 页面会把 WebSocket 推导成 `wss://<当前域名>`，隧道把 wss 转发回本机 5274；
- **语音媒体不过隧道**：实测 ICE 只有 `host` 候选、`relay=0`，媒体走同网段 P2P，隧道只承担信令
  （实测隧道边缘 RTT 约 270ms、首屏 0.5-2.2s，信令每条消息几百毫秒，玩家无感；我们这里隧道出口
  落在美国，所以比自签证书方案的几毫秒慢得多）；
- ⚠️ **域名每次重启都会变**（实测 `competitive-relate-must-rock` → `bingo-biological-decide-penn`，
  旧域名立刻返回 530），重启后要把新地址重新发给大家；
- ⚠️ cloudflared 快速隧道**官方不保证可用性**，也不该用于生产；正式上线请换成固定域名 + 自己的 TURN。

**B. 自签证书（没外网也能用，手机要装一次证书）**：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\make-lan-cert.ps1
# 产出 .tools\lan-cert\{lan.pfx, lan.cer, README.txt}
node server/dist/server.mjs --tls-pfx .tools\lan-cert\lan.pfx --tls-pass mmai-lan
```

- 证书 SAN 里带的是 **IP 类型条目**（`IP Address:192.168.1.100`），Chrome 才会认这个地址；
- 把 `lan.cer` 按生成的 `README.txt` 装到每台手机上：**Android** 设置→安全→加密与凭据→
  安装证书→**CA 证书**；**iOS** 装完描述文件后**还要**去 设置→通用→关于本机→证书信任设置
  手动打开信任（iOS 漏掉第二步就白装）；
- 之后手机访问 `https://192.168.1.100:5274/` 就能开麦。局域网内延迟只有几毫秒，比隧道快得多；
- 实测「用户点『继续访问』接受自签证书」的场景：Chrome 仍然认定为安全上下文，
  `getUserMedia` 照样 `GRANTED` —— 也就是说**不装证书也能开麦**，只是每次会看到红色警告。

> 服务器没配 TLS 时仍然照常跑 http，只是横幅会提醒「现在手机无法开麦，只能打字」。

**怎么确认某个地址到底能不能开麦**（把地址换成你要试的）：

```bash
node .verify/tunnel-check.mjs https://192.168.1.100:5274 --grant-mic
```

它会依次验证：页面 200、是本站页面、wss 握手收到帧、`isSecureContext`、
`mediaDevices` 存在且可调用，并**真的调一次 `getUserMedia`**。
（注意：自动化环境里不加 `--grant-mic` 会看到 `NotAllowedError`，那是浏览器自动拒绝弹窗，
不代表麦克风不可用 —— 这个坑很容易误判。）

### 打字端（公屏）做了哪些细节

- 消息带发送者昵称与时间（`chatTimeText`），自己的在右侧金色气泡；**全程 `{{ }}` 插值，不 `v-html`**
  （消息是别人发来的不可信内容，自检里有一条 XSS 断言）。
- **自动滚动**只在一个状态下做决定：贴底（距底 < 80px）就跟到底；正在往上翻历史时
  一个像素都不动，只点亮「↓ 有新消息」，点了才回到底部。
- 未读红点长在顶栏入口上；打开公屏即清零。刷新/重连后由服务器补发最近 60 条历史。
- 快捷短语（「我有线索要说」等）填进输入框而不是直接发出去，方便改；
  输入法组字中的回车不会误发（`isComposing` 判定）。
- 草稿存 `sessionStorage`，误触返回不丢字（切 tab 也不丢）。
- 服务端兜底：单条上限 200 字（超长按码点截断，不切坏 emoji）、空消息丢弃、
  同一座位 350ms 一条 + 每秒不超过 8 条的限流。
- `chat` 帧里**没有 `roleName` 等身份字段**（座位与角色的对应关系在复盘前不下发），
  自检脚本会对所有收帧做正则扫描，防止以后有人往消息里加身份信息。

### 快捷自检

```bash
node .verify/talk.mjs        # 假麦克风 + 真 WebRTC：建连成功、RTP 音频包真的到达、静音同步、信令不外泄
node .verify/prod-smoke.mjs  # 生产包冒烟：http 地址下说明麦克风不可用 + 真实点击发一条公屏
```

`talk.mjs` 用 `--use-fake-device-for-media-stream` 启动第二个无头浏览器（CDP 9223），
所以它验证的是**真的建立起了 P2P 并收到了音频 RTP 包**，不是只跑通信令。

## 一之四、玩家档案：免登录的个人信息存储

**一句话**：昵称、头像、战绩、对局历史存在房间服务器的一个 JSON 文件里，
**不用注册、不用登录** —— 档案跟着这台设备走。

### 为什么是「设备档案」而不是账号

第一次打开网页时本地生成一个随机 ID（`crypto.randomUUID()`，存在 `localStorage` 的
`mmai:player-id`），之后每次建房 / 加入都把 `playerId` 一起带上，服务器就用它认人：

- 没有密码、没有短信、没有注册页，打开就能玩；
- 代价一：换手机 / 换浏览器 / 清掉网站数据 = **一份新档案**（卡片上就写着这句话）；
- 代价二：**同一个浏览器开两个标签会共用一份档案**（同一局里坐两个座位，战绩只记一次）。

想让「换设备也能认回来」就必须有账号体系（手机号 / 第三方登录），那是后面的事；
现在的接口与存储结构可以直接长上去（把 `playerId` 换成账号 ID 即可）。

### 存了哪些字段

| 字段 | 例子 | 说明 |
| --- | --- | --- |
| 昵称 | `云中鹤` | 最多 16 字 |
| 头像 | `🔮` | emoji，最多 8 个码点；12 选 1，新设备随机给一个 |
| 战绩 | `{ games: 12, wins: 8, losses: 4, asMurderer: 3, murdererWins: 1 }` | 只由服务器在结算时累加 |
| 对局历史 | `{ at, roomCode, theme, playerCount, result, role, isMurderer }` | 保留最近 30 条，超出丢最旧的 |
| AI 引擎配置 | `{ provider, model, baseUrl }` | **不含 API Key**（见下）|

**API Key 永远不上服务器**：`PUT /api/profile` 里就算带了 `apiKey` 也会被直接丢掉，
并回一条警告，让客户端把「密钥只留在本机」写进界面（`src/services/profile.ts` 只发三个非敏感字段）。
剧本、线索、局内发言也一概不存 —— 战绩只记「谁赢了」，不记局内容。

### 战绩是服务器记的，不是前端报的

`Room.settle()` 在切到复盘阶段**之前**调一次 `recordStats()`，把每个真人座位的输赢、角色、
是否凶手交给 `ProfileStore.recordGame()`；`statsRecorded` 标记保证一局只记一次
（重复结算、断线重连都不会翻倍）。前端**没有任何上报战绩的接口**，所以改前端也刷不了战绩。

### 接口（普通 HTTP + JSON，挂在房间服务器同一个端口）

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| `GET` / `HEAD` | `/api/health` | `{ ok, version, profileCount, fileBytes, writes, uptimeMs }`，冒烟脚本用它确认后端在线 |
| `GET` | `/api/profile?id=<playerId>` | `{ profile }`；从未玩过则 `profile: null` |
| `PUT` | `/api/profile` | 写入 / 更新，body 上限 4KB，回 `{ profile, warnings }` |

- 不存在的 `/api/*` 回 404、方法不对回 405、body 太大回 413、ID 不合法回 400，
  限流命中回 429（带 `Retry-After`）；按 IP 的滑动窗口默认 10 秒 120 次。

跨域：`pnpm dev` 的页面在 5273、接口在 5274，所以接口带了 `Access-Control-Allow-Origin: *`。
这里没有 cookie、没有凭据，身份在 body / query 里，所以 `*` 是安全的、也是必需的。

### 文件在哪、怎么备份

```
server/data/profiles.json        # 就是它，纯 JSON，可以直接看 / 手工改
server/data/profiles.json.bak    # 每次落盘前的上一版
```

- 写入是**原子**的：先写 `profiles.json.tmp`，随后 `rename` 覆盖，再留一份 `.bak`；
  写到一半断电最多丢最后一次改动，不会把整份文件写坏。
- **文件坏了也不会崩**：解析失败就把坏文件改名成 `profiles.json.corrupt-<时间戳>` 保留证据，
  然后从空档案继续跑（启动横幅会说明）。
- 落盘有 250ms 去抖：一局打完连着写好几次也只落一次盘；`Ctrl+C` 关闭服务器时会 flush 兜底。
- 换存储位置：`node server/dist/server.mjs --data-dir D:\mmai-data`
  （也认环境变量 `MMAI_DATA_DIR` / `DATA_DIR`）。
- 备份就是复制那个 `profiles.json`；档案数超过 5000 份时按「最久没上线」淘汰。

### 界面上看到什么

设置页顶部是「我的档案」卡片：12 个头像、昵称输入框、同步状态、
四个战绩格（总局数 / 胜率 / 胜-负 / 拿凶手次数）和最近 5 局；
底部小字写明「只保存昵称、头像、胜负与对局摘要」，并显示当前同步到的接口地址。
**大厅与对局里的座位头像用的就是这张卡里的头像。**

- 服务器在线且已有档案 → 「已同步到服务器」，开机自动拉一次；
- 服务器在线但还没有档案（新设备第一次）→ 仍显示「已同步到服务器」，下面注明
  「服务器上还没有你的档案，开一局联机游戏（或点『立即同步』）就会创建」；
- 服务器没开（纯单机玩）→ 「仅本机（服务器未连接）」，本机照常记（`localStorage` 缓存），
  连上服务器后再点「立即同步」推上去。

### 隐私边界

- 服务器只存：`playerId`（随机串）、昵称、头像、战绩、对局摘要、AI 引擎的非敏感配置；
- 不存：API Key、手机号、IP（限流是内存里的滑动窗口，不落盘）、局内发言、剧本与线索；
- `playerId` 是**能力凭证**：知道它就能读写这份档案，所以它等于密码，别贴给人。
  强度是 uuid v4（122 位随机），猜不出来。

## 一之五、装到手机桌面（PWA：全屏启动，像 App 一样）

**一句话**：不用上应用商店。用手机浏览器打开一次，点「添加到主屏幕」，
之后从桌面图标进就是**全屏、没有地址栏**，也不会手滑下拉刷新把一局的进度刷掉。

### 怎么装

| 设备 | 步骤 |
| --- | --- |
| **iPhone / iPad（Safari）** | 底部「分享」→「添加到主屏幕」→ 从桌面图标打开（独立窗口，无地址栏）|
| **安卓（Chrome / Edge）** | 右上角「⋮」→「安装应用」/「添加到主屏幕」；能装时首页会顶出一条「装到桌面，全屏玩」的提示，点「安装」直接弹系统安装框 |
| **电脑（Chrome / Edge）** | 地址栏右侧的安装图标，或「⋮ → 安装迷案」；装完是一个独立窗口 |

装好之后 **设置页最下面那张「安装到桌面」卡片**会变成「✓ 正在以独立窗口运行」，
首页那条提示也不再出现（想再装可以在卡片里重来）。

### 它对玩家体验的三点实际影响

1. **全屏**：`display: standalone` + 顶栏留出刘海安全区（`env(safe-area-inset-top)`），
   状态栏和页面同色（`theme-color: #0b0d14`），看起来就是原生 App；
2. **不会误刷新**：独立窗口没有下拉刷新和地址栏，一局打到一半不会被手滑刷没；
3. **断网也能打开外壳**：Service Worker 预缓存了页面骨架，地铁里断网打开不会白屏
   （对局仍然要联网，档案与战绩照样实时读写）。

### 只有一个门槛：https（或 localhost）

浏览器只在**安全上下文**里允许注册 Service Worker 和安装，所以：

- `http://10.x.x.x:5274`（现在的局域网地址）→ **装不上**，设置页卡片会直接说明原因并给两个办法；
- `https://…` → 能装。两条现成的路：
  - 隧道：`pnpm tunnel` 给出的 `https://xxx.trycloudflare.com`（手机零配置，最省事）；
  - 自签证书：`pnpm cert` 然后 `pnpm server:tls`，手机装一次 `lan.cer`，之后用 `https://192.168.1.100:5275`。
- **iPhone 例外**：Safari 的「添加到主屏幕」不受 https 限制，用 http 也能加，
  加完同样是独立窗口（只是没有断网缓存）。

### 技术实现（想改的话看这几处）

| 文件 | 作用 |
| --- | --- |
| `public/manifest.webmanifest` | 名称、图标、`start_url: /`、`display: standalone`、竖屏锁定、两个桌面快捷方式 |
| `public/sw.js` | Service Worker：预缓存外壳；**导航网络优先**（新版本立刻生效）、`/assets/*` 缓存优先（文件名带 hash，永远安全）、`/api/*` 与 WebSocket 一律不碰 |
| `public/icons/*` + `scripts/make-icons.ps1` | 192 / 512 / maskable / apple-touch 图标，用 System.Drawing 现画（`pnpm icons` 可重新生成） |
| `src/services/pwa.ts` | 注册 SW、接管 `beforeinstallprompt`（自己控制弹窗时机）、判断 `installed / ready / manual / insecure` |
| `src/components/InstallCard.vue` | 设置页的卡片（三种状态三种文案）|
| `src/components/InstallBanner.vue` | 首页那条提示，可「以后再说」 |
| `server/src/static.ts` | `.webmanifest` 用 `application/manifest+json`；`sw.js` 与 manifest 设 `no-cache` + `Service-Worker-Allowed: /` |

> 一条重要的取舍：**Service Worker 不缓存 `/api/*`**。玩家档案与战绩必须实时，
> 缓存它只会让「打完一局战绩没变」这种 bug 变得没法复现。
> 想强制让所有人换新版本：改 `sw.js` 顶部的 `VERSION`（旧缓存会在 activate 时被清掉）。

### 快捷自检

```bash

```

Chrome 自己判定「0 个 manifest 错误」、SW 注册并激活 + 接管页面 + 缓存里有外壳而没有 `/api/*`、
**断网重载仍能进游戏并保留样式**、首页提示条与设置页卡片的文案、
以及模拟「从桌面图标启动」后文案切成「正在以独立窗口运行」、顶栏留出了安全区。

## 一之六、打包成桌面 App（双击即玩，不用装环境）

**一句话**：`pnpm app` 把整个游戏打成一个文件夹，**双击就开、关窗就退**；
连 Node 一起带上，拷到别人的 Windows 上也能直接玩。

```bash
pnpm app                                  # → 桌面\迷案（并在桌面建「迷案」快捷方式）
node scripts/make-app.mjs --out=D:\ghost  # 换个位置
node scripts/make-app.mjs --no-shortcut   # 不建快捷方式（只想要绿色版）
```

产出：

```
迷案/
├── 迷案.vbs            ← 双击这个（启动时无黑窗）
├── 迷案.cmd            ← 同一件事，带控制台，排障时用它看输出
├── launcher.mjs        选空闲端口 → 起服务器 → 开独立窗口 → 窗口关掉就退出
├── server.mjs          房间服务器单文件（ws 已内联，零依赖）
├── package.json        只为让服务器把「本文件夹」认作根目录
├── dist/               前端（含 PWA 的 manifest / sw / 图标）
├── runtime/node.exe    自带的 Node（所以目标机器什么都不用装）
├── 图标.ico            16/32/48/128/256 五档
└── 使用说明.txt
```

它是怎么变成「一个 App」的：

1. **窗口没有地址栏和标签栏** —— 启动器用 Edge/Chrome 的 `--app=http://127.0.0.1:5274/`，
   并用 `迷案\profile\` 做专属浏览器配置目录，这份数据只属于这个 App；
2. **关窗即退** —— 启动器盯着窗口进程，窗口一关就结束服务器并清掉 `app.lock`，不留后台进程；
3. **单实例** —— 已经有一份在跑时，再双击只补开一个窗口，不会起第二个服务器去抢同一份
   `profiles.json`；
4. **端口自选** —— 从 5274 起试 24 个端口，被占用自动换；起不来会弹系统消息框说明原因
   （App 没有控制台，弹框是唯一能被看到的失败方式）。

数据都在 App 文件夹里：`迷案\server\data\profiles.json`（档案与战绩）、`迷案\profile\`（浏览器配置）、
`迷案\logs\server.log`（日志）。**删掉整个文件夹 = 干净卸载**：不写注册表、不装服务。

> 三个坑都在打包脚本 / 启动器里钉住了：
> ① `.vbs` 必须是**纯 ASCII** —— wscript 按 ANSI 解码 UTF-8 脚本，中文注释会让「双击没反应」；
> ② 内联 `ws`（CJS）进 ESM 需要 `createRequire` 的 banner，否则启动即 `Dynamic require of "events"`；
> ③ 隐藏方式启动会把 `SW_HIDE` 一路传给 Edge，窗口建出来了但**看不见**
>    （任务栏有、屏幕上没有，`MainWindowHandle` 还是 0）—— 启动器用 `EnumWindows` 按 PID
>    找到它的顶层窗口，再 `ShowWindow(SW_SHOWNORMAL)` 拉出来并置前。

> 注意：桌面版占着 5274 时 `pnpm server` 会起不来 —— 两个入口别同时开。

## 三、节奏规范（按人数）

这是本版最核心的一次升级：**一局跑几轮、什么时候发线索、什么时候解锁凶手特权，全部由人数决定**，
并且写死在规则层 `src/services/rules.ts`（唯一事实来源，状态机 / 阅读时长 / AI 指令 /
字数校验 / 进度条都从这里取值，避免各处硬编码）。

| | **4 人局** | **5 人局** | **6 人局** |
| --- | --- | --- | --- |
| 定位 | 极简紧凑 · 高信息密度 | 标准均衡 · 经典配置 | 多线并行 · 防边缘化 |
| 发言轮次（硬性上限） | **2 轮** | **3 轮** | **3 轮** |
| 搜证环节 | 无（线索由系统发放） | 无（线索由系统发放） | **每轮 1 次，每人每轮 2 次** |
| 阅读时长 | 10 分钟 | 15 分钟 | 20 分钟 |
| 角色剧本字数 | 1500-1900 字 | 1900-2400 字 | 2300-2800 字 |
| 独立支线任务 | 无 | 无 | **每人 1-2 条** |
| 提前结算阈值 | 3 人指认同一人 | 4 人指认同一人 | 5 人指认同一人 |
| 防冷场 AI 提示 | 关 | 关 | 半场无人发言时自动触发 |

### 轮次结构

```
第 1 轮  破冰与时间线对齐      发放第一批：基础现场线索（现场勘察 / 死因 / 人际关系）
第 2 轮  核心冲突与秘密碰撞    发放第二批：深度线索（私人物品 / 隐藏日记）+ 自动解锁凶手特权
第 3 轮  逻辑收网与最终陈述    发放第三批：决定性线索，随后强制关闭发言
        ↓
个人整理（5 分钟）→ 最终投票 → 复盘结算
```

- **4 人局只有 2 轮**，第二轮的定位是「核心冲突 + 逻辑收网」的合并版；第三批决定性线索在
  第 2 轮结束后立即补发，然后强制进入整理与投票。
- **6 人局每轮陈述后都有一次搜证**。玩家自己翻出来的线索与系统发放的三批线索**互不重复**：
  前者是散落在地点里的物证，后者是随轮次推进逐步公开的官方信息。
- 进度条由 `flowSteps` 按人数与轮次动态生成，所以 4 人局看到的是
  `组局 → 下发剧本 → 阅读 → 第 1 轮 → 摸底 → 第 2 轮 → 整理 → 投票 → 复盘`。

### 信息可见性（谁能看到什么）

剧本杀的核心是**信息不对称**，所以这一版对「哪些数据能出现在谁的屏幕上」做了明确收口：

| 信息 | 凶手端 | 平民端 | 上帝视角（演示） | 复盘 |
| --- | --- | --- | --- | --- |
| 自己的阵营（好人 / 凶手）与胜负条件 | ✅ 阅读页阵营卡 + 陈述页提醒 | ✅ 同上 | ✅ | ✅ |
| 凶手特权的直觉提示 | ✅ 第 2 轮起，标注「仅你可见」 | ❌ **数据层就不持有** | ✅ 标注「上帝视角 · 正常对局你看不到」 | ✅ 全员公开 |
| 其他角色的剧本 | ❌ | ❌ | ✅ | ✅ |
| 私有线索 | 仅自己的 | 仅自己的 | 全部 | 全部 |
| 全局真相 / 真凶姓名 | ❌ | ❌ | ❌（`global_truth` 不进游戏内视图） | ✅ |

三条实现要点：

1. **上帝视角默认关闭**，并且**不写入本地存储**（`settings.ts` 只持久化昵称与 AI 配置）——
   否则上一局开过之后，下一局平民一进房间就直接看到凶手特权。
2. **纵深防御**：`triggerPrivilege()` 在平民端**根本不把提示写进本地状态**（`stores/game.ts`），
   所以就算将来某个视图忘了加判断也渲染不出东西；需要展示它的复盘页直接从剧本包读取。
3. 阵营卡用**第二人称**（「你就是本案真凶」/「你是清白的」），并写清胜负条件
   （平民必须把真凶投成**唯一**最高票，平票即凶手逃脱）。

> ⚠️ 边界：本版是**单机离线架构**，整个剧本包（含 `murderer_privilege`）都在客户端内存里，
> 上述隔离是**界面与状态层**的隔离，不是密码学隔离。正式多人对局必须由服务端按座位下发：
> 凶手端只拿自己的剧本 + `murderer_privilege`，平民端连字段都收不到。

### 动态加速（提前结算）

每轮结束会先做一次**意向投票**（摸底，不影响最终投票）。满足任一条件时系统提示提前结算：

1. 在**倒数第二轮**结束时，达到人数对应的票数阈值（4/5/6 人局分别为 3/4/5 票）；
2. 三批线索全部发放且现场线索全部被翻出（4/5 人局没有搜证环节，发完三批即等同于全部曝光）。

玩家可以选择「提前结算 · 进入整理」跳过剩余轮次，也可以选择「继续第 N 轮」。

### 防冷场（6 人局）

若某一轮时间过半仍**无人发言**，系统自动播报一条 **AI 侦探提示**：引用本轮已发放的线索给出
具体的讨论抓手（例如「关于『随船医官的日志缺了两页』，谁最先能说清？」），每轮最多触发一次。

### 动态长度与复杂度控制

剧本长度按人数硬性约束，并写进了 System Prompt（见 `systemPrompt.ts` 的 `DYNAMIC_LENGTH_RULES`）：

- 4 人局：1500-1900 字，剧情高度浓缩，禁止无关支线，所有角色的秘密高度交叉；
- 5 人局：1900-2400 字，允许 1 个承担线索串联功能的边缘角色，加强情感与动机描写；
- 6 人局：2300-2800 字，每人额外生成 1-2 条与主线无关的独立支线任务，防止玩家挂机。

**一份长剧本，三个长度档位**：模板作者只写一份 2300-2800 字的多段落长剧本，段落按重要性排序
（小传 → 动机 → 案发当日回忆 ×2 → 可裁剪的补充段落 → 行为准则），
`src/services/templates/assemble.ts` 的 `assembleScript()` 按目标字数从前往后取段落，
**行为准则永远保留在最后**，因此 4/5/6 人局拿到的是真正的浓缩版，而不是被截断的残本。

**AI 分阶段生成 + 自动重写**：真实模型不再一次输出整桌剧本，而是先锁定案件骨架，
再逐个角色生成正文。每次调用都显式携带 `max_tokens`，单个角色不达标会单独重写；
最终合并后再由 `validateScriptPackage` 检查人数、真凶、线索、时间线和全角色字数。

### AI 剧本防重复

- 每次真实大模型生成都会附带随机局标识与最近案件摘要，要求重新设计凶手、关系、核诡、手法和关键物证。
- 生成完成后会计算剧本指纹；角色或线索顺序变化不能绕过查重。
- 首次检测到重复会自动要求模型重写；第二次仍重复则拒绝进入游戏。
- 最近 30 场记录保存在当前设备；设置页可以手动清空，之后相同案件可能再次出现。
- 离线模拟引擎只有有限内置模板，不承诺无限不重复；命中最近记录时会明确拒绝并建议更换题材或使用真实大模型。

如果模型返回 `finish_reason=length`，系统会明确提示输出被截断，而不是把残缺 JSON
当成完整剧本继续使用。设置页可调整单次最大输出 Token，建议至少 8192。

## 四、AI 引擎：离线可用，随时切真实大模型

设置页可在两种引擎之间切换：

**1）离线模拟引擎（默认）**
`src/services/templates/` 内置两套完整剧本（民国远洋邮轮 / 现代雪山山庄），每套 6 个角色。
每个角色是一份 2300-2800 字的多段落长剧本（含具体钟点），外加 2 条独立支线任务；
两套题材各有三批系统线索（共 11 条）与 6 个搜证地点。
按 4/5/6 人自动裁剪到对应字数档位，并且**任何题材都能开局**（未命中关键词时改写题材名后复用就近模板）。

**2）真实大模型（OpenAI 兼容）**
`src/services/systemPrompt.ts` 里的 `SYSTEM_PROMPT` **逐字取自《指令.docx》**，再加两个升级模块
（【动态长度与复杂度控制规则】【多轮节奏与线索分批发放】），作为 system message 发送；
用户消息由 `buildUserPrompt(人数, 题材)` 生成，里面写明了本局的字数区间、轮次数与线索批次数。
返回内容会剥掉 markdown 围栏、解析 JSON，再交给 `validateScriptPackage` 校验，
**校验不通过的剧本不会进入游戏**（字数不合规会先触发一次自动重写）。

已内置 DeepSeek / 通义千问（兼容模式）/ Kimi / 本地 Ollama 的地址与模型名一键填充。

> ⚠️ 浏览器直连大模型可能被 CORS 拦截。正式部署时应由后端（NestJS / FastAPI）代理转发，
> 前端只把 `baseUrl` 指向自己的网关即可。

### 「生成剧本失败」是怎么处理的（联机局曾经会误报）

修过一个真实故障：把引擎切成「真实大模型」之后，**联机局也会在「剧本下发」页显示「生成失败」**。
根因是职责重叠 —— 联机模式下剧本由房间服务器生成下发（服务器才是权威），
但客户端进到下发页时又自己生成了一遍：本地没填 Key / 请求失败就抛错，
还把本地阶段打回房间，跟服务器的阶段对着干。

现在的规则：

1. **联机局客户端绝不生成**：`game.dealScript()` 在 `state.online` 时直接返回，
   下发页显示「服务器正在生成这一局」，等服务器把剧本推过来就自动进阅读页。
   自检里断言了这条路径下客户端的大模型请求数必须是 **0**。
2. **单机局配置错了要看得见、也要能开起来**：选了真实大模型却没填 Key 时，
   不再白等两次请求超时，直接给出可执行的原因（去「设置」补 Key，或切回离线引擎），
   失败卡片上的主按钮就是「改用离线引擎，先开这一局」——派对游戏不能卡在开局。
3. **设置页提前警告**：选了真实大模型但 Key 为空时，接口配置区顶部直接标红提醒。

自检：`node .verify/gen.mjs`（**20 / 20 通过**）——覆盖联机三种引擎配置（离线 / 线上没填 Key /
线上地址是坏的）都必须走到阅读页拿到剧本、且客户端不发大模型请求，以及单机失败后一键兜底能开局。

## 六、数据契约（与《指令》严格一致）

```jsonc
{
  "game_config": { "theme": "", "player_count": 5, "background_story": "" },
  "global_truth": { "murderer_name": "", "cause_of_death": "", "absolute_timeline": "" },
  "roles": [{
    "name": "", "identity": "", "is_murderer": false,
    "surface_task": "", "deep_task": "", "personal_timeline": "",
    // 字数按人数：4 人 1500-1900 / 5 人 1900-2400 / 6 人 2300-2800（非空白字符）
    "full_script": "",
    "side_quests": ["6 人局必填：与主线无关的独立支线任务"]
  }],
  "murderer_privilege": { "intuition_hint": "" },
  "public_clues": ["", "", ""],

  // 本项目补充的可选扩展（缺失时前端会自动兜底）
  "clue_batches":      [{ "tier": 1, "title": "第一批 · 基础现场线索", "clues": ["", ""] }],
  "private_clues":     [{ "role_name": "", "text": "" }],
  "search_locations":  [{ "name": "", "clues": ["", ""] }]
}
```

- `clue_batches` 缺失时，`normalizeScriptPackage` 会把 `public_clues` 按 4:4:2 自动切成三批，
  保证轮次推进与线索发放永远可玩；`public_clues` 始终等于三批的并集。
- `search_locations` 缺失时会按现场地点自动切分，保证「自由搜证」不会空转。
- 服务端下发时应**按座位裁剪**这个包（见「信息可见性」的边界说明）。

TypeScript 类型见 `src/types/script.ts`，校验逻辑见 `src/services/validator.ts`。

## 七、接入后端时怎么改

1. 后端按 `src/services/ws.ts` 的 `RoomEvent` 契约推送事件；
2. 配置环境变量 `VITE_WS_URL=ws://your-host/ws`（不配则继续走本地模拟）；
3. 把 `stores/game.ts` 中标注 `TODO(ws)` 的本地动作替换为 `socket.send(...)`，并在事件回调里调用对应 action；
   **轮次推进（`beginRound` / `endRound` / `checkAcceleration`）建议整体上移到服务端**，
   由服务端做权威判定，前端只负责渲染与上报，避免各端轮次不同步；
4. **按座位下发剧本**：凶手端才带 `murderer_privilege` 与自己的 `full_script`；
5. **视图层（`views/`）不需要任何改动** —— 它们只读 store。

## 九、已知边界

- **联机版是真的多端对局**：房间服务器持有全部真相，按座位裁剪后下发；客户端只发意图。
  但它仍是**临时房间**：房间只在内存里（服务器一重启就没了）、没有账号体系
  （知道房号就能进）。跨网络要靠隧道（README「沟通」一节给了命令），
  那条路实测可用但没有可用性承诺；房间服务器自己不提供公网穿透。
- **语音是 P2P 直连，没有 TURN 兜底**：同 Wi-Fi 或能用隧道+STUN 打通时都正常，
  但对称 NAT 场景需要自己搭 coturn；路由器开「AP 隔离」也会导致连不上
  （界面会显示「连不上」并说明原因，此时改用公屏打字）。
- **开麦必须 https**：这是浏览器的硬规则，不是本项目能绕过的限制 ——
  用 `http://<局域网 IP>:5274` 时手机拿不到麦克风（打字不受影响）。
  要么用隧道（手机零配置），要么用 `scripts/make-lan-cert.ps1` 自签证书（手机装一次证书）。
- **装到桌面（PWA）同样必须 https / localhost**：Service Worker 与系统安装入口都只在安全上下文里
  可用，`http://<局域网 IP>:5274` 装不上（设置页会说明原因）。用隧道地址，或自签证书后的
  `https://…:5275`。**iPhone 是例外**：Safari 的「添加到主屏幕」不受此限，http 也能加，
  加完同样是独立窗口，只是没有断网缓存。另外 iOS 清掉网站数据会连桌面图标的缓存一起清，
  需要重新打开一次线上地址。
- **公屏是明文广播**：消息经服务器转发但不落盘、不做内容审核，
  适合熟人局；公屏里说的话对全桌可见，别把秘密线索念出来。
- **玩家档案免登录 = 跟着设备走**：`playerId` 存在 `localStorage`，换手机 / 换浏览器 /
  清网站数据就是一份新档案（要跨设备认人就得加账号体系）；同浏览器开两个标签会共用一份档案。
  `playerId` 本身是能力凭证（等于密码），别贴给别人。档案文件是**明文 JSON**，
  适合本机 / 熟人小圈子，别把 `server/data/` 放到公网目录里；API Key 从不上服务器。
- **单机模式**（首页「单人试玩」/ 演示深链）没有后端：其他座位由本地模拟玩家填充，
  发言按轮次风格生成、投票为前端启发式，仅用于跑通流程与演示。
  单机模式下**信息隔离只在前端层面**（整个剧本包都在客户端），
  正式多人对局必须走联机模式（服务器按座位下发，尤其是 `murderer_privilege` 与 `global_truth`）。
- **联机模式下轮次与提前结算由服务端权威判定**（`server/src/room.ts`），
  所以不会再出现各端轮次漂移；单机模式仍是前端判定。
- 4/5 人局没有搜证环节（按节奏规范，线索由系统按轮次发放）；`search_locations` 数据仍保留，
  后续想把搜证开放给所有人数，只需把 `rules.ts` 里的 `searchRounds` 改成非 0。
- 复盘判定的「表层/深层任务是否达成」是初版简化规则（表层=没被半数以上的人盯上；深层=阵营获胜），
  正式版应交由服务端按剧本埋设的判定条件裁决（联机版的胜负判定已在服务端，任务达成仍是简化规则）。
- 未成年人防沉迷、实名认证、内容安全审核属于阶段 3（商业化）的内容，本版未实现。
